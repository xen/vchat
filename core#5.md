# Политики безопасности виджета и сервиса (Core #5)

## 1. Введение
Обеспечение безопасности платформы «vbudushee» строится на принципе эшелонированной защиты (Defense in Depth). Данный документ описывает механизмы защиты данных клиентов, предотвращения несанкционированного доступа к LLM-ресурсам и безопасной интеграции виджета чата на сторонние сайты.

---

## 2. Безопасность виджета (Client-Side Security)

Интеграция виджета осуществляется через вставку JavaScript-кода. Для защиты этого процесса используются следующие механизмы:

### 2.1. Ограничение доменов (Domain Whitelisting)
- В настройках проекта администратор указывает список разрешенных доменов (Allowed Domains).
- Сервер проверяет заголовок `Origin` или `Referer` при инициализации виджета и установке WebSocket-соединения.
- Если домен отсутствует в списке, инициализация блокируется (статус 403 Forbidden).

### 2.2. Content Security Policy (CSP)
Для корректной работы виджета на сайте клиента рекомендуется настроить следующие CSP-директивы:
- `script-src`: разрешить загрузку скрипта с домена `vbudushee.ru`.
- `connect-src`: разрешить WebSocket-соединения (`wss://vbudushee.ru`) и API-запросы.
- `frame-src`: если виджет использует iframe для изоляции стилей.

### 2.3. Изоляция сессий чата
- Каждая сессия анонимного пользователя в виджете получает уникальный `user_uid`.
- Доступ к истории конкретного чата через WebSocket защищен подписанным токеном (`payload`), который имеет ограниченный срок жизни (по умолчанию 1 час).
- Токен генерируется сервером и привязан к паре `(user_id, chat_id)`.

## 3. Безопасность сервиса (Server-Side Security)

### 3.1. Защита API и CSRF
- Все модифицирующие операции (POST, PUT, DELETE) требуют передачи заголовка `X-CSRFToken`.
- Токен проверяется на стороне сервера на соответствие текущему авторизованному пользователю.
- Для HTMX-запросов используется интеграция с Django-style CSRF защитой.

### 3.2. Изоляция данных (Multi-tenancy)
- **Уровень БД**: Каждая таблица, содержащая чувствительные данные (`Project`, `Source`, `Document`, `Chunk`, `Chat`), имеет поле `project_id`.
- **SQL-запросы**: Все выборки в `views` обязательно включают фильтр по `project_id` и проверку прав текущего пользователя через таблицу `ProjectUser`.
- **Векторный поиск**: Поиск похожих фрагментов (Similarity Search) всегда ограничен `WHERE project_id = :pid`.

### 3.3. Безопасная загрузка файлов (TUS Protocol)
- Загрузка документов (PDF, Docx) реализована через протокол TUS, что позволяет проверять метаданные файла до начала полной загрузки.
- Файлы сохраняются в изолированные директории `media/uploads/{project_id}/`.
- Прямой доступ к файлам по URL закрыт; выдача контента происходит через контроллер с проверкой прав доступа (`secure_download`).

---

## 4. Защита LLM-слоя и RAG

### 4.1. Предотвращение Prompt Injection
- Системный промпт (System Prompt) проекта жестко фиксируется на стороне сервера и не может быть изменен конечным пользователем через API чата.
- Пользовательский ввод обрабатывается как контент, отделенный от инструкций модели.
- Реализована фильтрация стоп-слов и ограничение длины входящего сообщения.

### 4.2. Конфиденциальность данных
- Персональные данные (PII), найденные в документах, могут быть анонимизированы перед отправкой в LLM (опционально, зависит от настроек проекта).
- Использование локальных моделей (Local LLM) позволяет полностью исключить передачу данных внешним провайдерам (OpenAI/Anthropic).

---

## 5. Мониторинг и лимиты (Rate Limiting)

### 5.1. Ограничение потребления ресурсов
- Установлены лимиты на количество сообщений в минуту для одной сессии чата (защита от ботов).
- Лимиты на количество токенов и объем индексируемых данных в зависимости от тарифного плана проекта.

### 5.2. Логирование инцидентов
- Все попытки несанкционированного доступа (Bad CSRF, Invalid Project ID) логируются с указанием IP-адреса и метаданных запроса.
- Администраторы получают уведомления о подозрительной активности (например, массовая выкачка данных через чат).

---

## 6. Резюме
Политика безопасности vbudushee обеспечивает надежную изоляцию клиентских данных и защищает инфраструктуру от злоупотреблений. Ключевым элементом является сочетание строгой проверки прав на стороне сервера с современными веб-стандартами безопасности (CSP, CORS, TUS).
