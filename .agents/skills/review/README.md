# review

Краткие комментарии ревью с учётом проекта. Определение места, проблема, исправление. Без лишних вступлений.

## Что делает

Проверяет diff, читает `kb/index.md` и только релевантные файлы KB, затем
генерирует комментарии ревью в формате `L<line>: <severity> <problem>. <fix>.`.
Одна строка на одно замечание. Эмодзи важности: 🔴 bug, 🟡 risk, 🔵 nit,
❓ question. Убирает фразы вроде "Я заметил, что...", смягчения формулировок и
пересказ того, что и так видно в diff. Сохраняет точные номера строк,
символы в обратных кавычках и конкретные исправления.

Авто-ясность: отключает краткий режим для security-замечаний уровня CVE,
архитектурных разногласий и onboarding-контекста, где автору нужно *почему*.
Для остального возвращается к краткому режиму.

Только вывод — не ставит approve, не запрашивает изменения и не запускает линтеры.

## Как вызвать

```bash
/review
```

Также срабатывает на фразы "review this PR", "code review", "review the diff".

## Пример вывода

```text
L42: 🔴 bug: user can be null after .find(). Add guard before .email.
L88-140: 🔵 nit: 50-line fn does 4 things. Extract validate/normalize/persist.
L23: 🟡 risk: no retry on 429. Wrap in withBackoff(3).
L107: ❓ q: why drop the cache here? Reads on next request will miss.
```
