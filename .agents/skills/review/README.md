# review

Краткие комментарии ревью с учетом проекта: место, проблема, исправление. Без
лишних вступлений.

## Что делает

Проверяет изменения, читает `kb/index.md` и только релевантные файлы KB, затем
генерирует комментарии ревью в формате
`L<line>: <severity> <problem>. <fix>.`

Одна строка на одно замечание. Эмодзи важности: 🔴 bug, 🟡 risk, 🔵 nit,
❓ q. Скилл убирает фразы вроде "Я заметил, что...", смягчения
формулировок и пересказ того, что уже видно в изменениях. Сохраняет точные номера
строк, символы в обратных кавычках и конкретные исправления.

Краткий режим отключается для замечаний по безопасности уровня CVE,
архитектурных разногласий и вводного контекста, где автору нужно объяснить
причину. Для остального формат остается компактным.

Скилл только выводит ревью: не ставит одобрение, не запрашивает изменения и не
запускает линтеры.

После ревью скилл предлагает запустить `kb-update`, чтобы сохранить новые
повторяемые проектные правила. KB не обновляется без отдельного запроса
пользователя.

## Как вызвать

```bash
/review
```

Также срабатывает, когда пользователь просит ревью кода, проверку изменений
или ревью запроса на слияние.

## Пример вывода

```text
L42: 🔴 bug: `user` может быть null после `.find()`. Добавь проверку перед `.email`.
L88-140: 🔵 nit: функция на 50 строк делает 4 вещи. Вынеси проверку, нормализацию и сохранение.
L23: 🟡 risk: нет повторной попытки при 429. Оберни вызов в `withBackoff(3)`.
L107: ❓ q: зачем сбрасывать кэш здесь? Следующий запрос гарантированно промахнется.
```
