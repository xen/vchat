# Task: Temporal Evidence для RAG без LLM-прохода

## Goal

Спроектировать слой извлечения временных свидетельств для RAG без отдельного
LLM-прохода. Система не должна сама жестко решать бизнес-смысл каждой даты
через набор хрупких правил. Она должна находить только релевантные временные
утверждения из найденных фрагментов, связывать дату с ближайшим текстовым
контекстом и передавать это в генерацию ответа.

Задача описывает переносимый контракт для другой коммерческой части проекта.
В текущем репозитории `vchat` реализация не выполняется.

## Guard Rails

- Не делать отдельный LLM-проход для анализа страницы.
- Не доливать в prompt все даты со страницы.
- Не строить большую бизнес-онтологию правил вида "если конкурс + дата, значит
  дедлайн".
- Не добавлять fallback-и и молчаливую деградацию. Если extractor не может
  уверенно нормализовать дату, он должен вернуть evidence без нормализованного
  диапазона или пропустить его по понятному правилу.
- Не реализовывать это в текущем репозитории `vchat`.
- Не смешивать извлечение evidence, retrieval-ранжирование и политику
  финального ответа в один слой.

## Iterations

1. Temporal Evidence Extractor

   Реализовать локальный модуль, который принимает текст чанка и возвращает
   список временных свидетельств.

   Пример результата:

   ```json
   {
     "date_text": "с 1 по 15 июня 2026 года",
     "normalized": {
       "start": "2026-06-01",
       "end": "2026-06-15"
     },
     "sentence": "Конкурс проводится с 1 по 15 июня 2026 года.",
     "local_context": "конкурс проводится",
     "subject_terms": ["конкурс"],
     "predicate_terms": ["проводится"],
     "confidence": "medium"
   }
   ```

   Критерий завершения: extractor стабильно находит даты и ближайшую связь в
   предложении, но не классифицирует бизнес-статус страницы.

2. Фильтрация релевантных temporal evidence

   Добавить слой, который выбирает evidence только из top-N retrieval-чанков и
   только если дата находится в смысловом окружении вопроса или ответа.

   Принцип: дата рождения автора не должна попадать в контекст ответа про
   участие в конкурсе, если retrieval не выбрал этот фрагмент как релевантный.

   Критерий завершения: в prompt попадает не больше 3-5 temporal evidence на
   ответ, каждое привязано к конкретному source, chunk и sentence.

3. Интеграция в RAG Prompt

   Передавать temporal evidence отдельным блоком рядом с источниками:

   ```text
   Current date: 2026-06-18

   Temporal evidence:
   1. Source: ...
      Sentence: "Прием заявок проводится с 1 по 15 июня 2026 года."
      Parsed range: 2026-06-01 to 2026-06-15
      Local relation: "прием заявок проводится"
   ```

   Критерий завершения: LLM видит текущую дату, исходное предложение,
   нормализованную дату и локальную связь, но финальный вывод остается за
   моделью.

4. Кэш и безопасность свежести

   Для ответов, где в prompt добавлены temporal evidence, включить в cache key:

   - текущую дату или дневной bucket;
   - хеш списка temporal evidence;
   - хеш retrieval-контекста.

   Критерий завершения: ответ, сгенерированный до истечения окна, не может быть
   переиспользован после смены даты без пересборки контекста.

5. Административная наблюдаемость

   Добавить отладочный вывод для страницы или ответа:

   - какие temporal evidence найдены;
   - из какого предложения;
   - какой normalized range;
   - почему evidence попал или не попал в prompt.

   Критерий завершения: ошибочные или шумные даты можно диагностировать без
   чтения логов LLM.

## Verification Criteria

- Unit-тесты extractor-а:
  - "Конкурс проводится с 1 по 15 июня 2026 года" дает range
    `2026-06-01..2026-06-15`.
  - "Автор родился в 1984 году" дает date evidence, но не application/event
    window.
  - "Опубликовано 3 июня 2026 года" не попадает в prompt для вопроса "как
    участвовать в конкурсе?".
  - "Прием заявок до 15 июня 2026 года" дает end date.
  - Несколько дат в одном тексте ограничиваются релевантными sentence-level
    evidence.

- Интеграционный тест RAG:
  - вопрос: "Как участвовать в конкурсе?"
  - текущая дата: `2026-06-18`
  - source sentence: "Прием заявок проводится с 1 по 15 июня 2026 года."
  - ожидаемый инвариант: prompt содержит temporal evidence с range и текущей
    датой.

- Проверка отсутствия прогнивания правилами:
  - `rg` по модулю не должен показывать разросшиеся списки доменных
    бизнес-правил для конкретных типов страниц.
  - extractor возвращает evidence, а не финальные решения вроде
    `contest_expired=True`.
