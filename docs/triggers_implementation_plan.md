# План реализации раздела "Триггер"

## Цель

Сделать управляемые триггеры для публичного чат-виджета: виджет понимает URL страницы, получает релевантные приглашения, показывает их после признаков чтения страницы и открывает чат с отправкой выбранного сообщения. Для страниц без готовых триггеров показываются стандартные шаблоны.

## Модель данных

1. `Source.config.trigger_rules`
   - regex-правила страниц, для которых нужны триггеры;
   - хранятся рядом с существующими crawler/ignore rules внутри JSON config источника.

2. `Page.has_triggers`
   - флаг, что URL страницы попал под trigger regex источника;
   - выставляется во время краулинга при создании/обновлении страницы.

3. `Page.triggers`
   - JSON-массив приглашений страницы;
   - каждый элемент хранит `key`, `text`, `source`, `generated_at`.

4. `trigger_response_cache`
   - `page_id`, `trigger_key`.
   - `prompt_hash`.
   - `response_text`, `full_context`, `used_chunks`.
   - `provider`, `model`, `tokens`.

## Админка

1. Добавить пункт меню `Триггер` в настройки.
2. На странице раздела:
   - textarea со стандартными триггерами, по одному на строку;
   - regex-правила по источникам;
   - кнопка сохранения, которая применяет правила к существующим страницам;
   - кнопка генерации для страниц без готовых триггеров.
3. При сохранении правил пересчитывать `Page.has_triggers` для существующих страниц источника. Генерация запускается только отдельной кнопкой.

## Генерация

1. Для страницы брать `title`, `uri`, первые N символов `content`.
2. Отправлять AI provider structured prompt:
   - вернуть JSON-массив строк;
   - 10 приглашений;
   - каждое до 10 слов;
   - релевантно содержимому страницы;
   - язык страницы/заголовка.
3. Валидировать ответ: список строк, trimmed, max 10 слов, dedupe.
4. Записывать `Page.triggers` только для страниц с `has_triggers=true`, где еще нет готового массива триггеров.

## Публичный виджет

1. Backend уже отдает JS через `/widget`; расширить шаблон.
2. JS считывает:
   - `window.location.href`;
   - `document.title`;
   - пользовательские атрибуты контейнера.
3. `GET /api/triggers/resolve?url=...&title=...`
   - если URL есть в `page` и есть триггеры, вернуть их;
   - если нет, вернуть стандартные шаблоны с подстановкой `{title}`.
4. После задержки и скролла показать анимированное приглашение над кнопкой.
5. При клике открыть iframe и передать в чат `postMessage`.

## Клик и кэш ответа

1. Iframe чата принимает `postMessage` с `{type: "vchat_trigger", page_id, trigger_key, text}`.
2. Chat JS отправляет в WebSocket JSON-сообщение с типом `trigger_prompt`.
3. Backend:
   - сохраняет user message;
   - если есть `trigger_response_cache`, стримит сохраненный ответ частями как обычный ответ;
   - если кэша нет, генерирует обычным RAG-путем и после успешного ответа пишет кэш.

## Страница информации о странице

1. В `document_detail.html` добавить блок `Триггеры`.
2. Показывать text и source.
3. Показывать кэшированные ответы по каждому триггеру: provider/model/tokens/date и первые строки ответа.

## Тесты

1. Unit-тесты helper-функций: default trigger rendering, URL matching, response parsing.
2. View-тесты:
   - resolve возвращает defaults;
   - resolve возвращает page triggers;
   - settings save создает/обновляет rules.
3. WebSocket-тест cached flow: trigger prompt с готовым кэшем стримит сохраненный ответ без provider call.

## Этапы

1. База, модели, routes, базовая админка.
2. Widget resolve/show/click + postMessage.
3. WebSocket cached response flow.
4. AI generation command/button.
5. Статистика на странице документа.
6. Тесты и визуальная проверка локальной админки/виджета в in-app browser.
