### 1. Архитектурная спецификация системы

Разработана детальная архитектурная спецификация сервиса «ИИ-агент-чат-бот», включающая описание всех уровней системы в соответствии с методологией C4 Model.

**C4 Model, Уровень 1 (System Context):** описано взаимодействие сервиса с экосистемой АС «ВБУДУЩЕЕ» — портал Битрикс, хранилище материалов Заказчика, GigaChat API, роли Посетителя портала и Администратора/Технолога.

**C4 Model, Уровень 2 (Containers):** детализированы внутренние компоненты — Web-Widget (JS/Snippet), Backend API (Python/FastAPI), Индексатор (Celery), Векторная БД (PostgreSQL + PGVector), реляционная БД для хранения истории диалогов, системных настроек и логов аудита.

**Схема RAG-конвейера (Flowchart):** описан полный процесс в двух режимах:
- **Offline/Sync (подготовка знаний):** извлечение текста из документов Заказчика (Word, Excel, PDF, PPTX) → нормализация → разбиение на чанки → генерация эмбеддингов → сохранение в векторную БД.
- **Online (обработка запроса):** вопрос пользователя → семантический поиск Top-K чанков → формирование промпта → проверка безопасности (Guardrails) → запрос к GigaChat API → пост-обработка и добавление ссылок на источники → валидация ответа → потоковая выдача в виджет.

**Стек технологий:** Python, GigaChat API (версия MAX и выше, включая модели для построения эмбеддингов), PostgreSQL + векторное расширение, Docker-контейнеры (совместимость с Kubernetes), Prometheus/JSON-логирование.

### 2. OpenAPI-спецификация публичного API (VChat Public API v1.0.0)

Разработана и согласована OpenAPI 3.0 спецификация публичных методов сервиса, описывающая ключевой эндпоинт:

**`GET /api/update`** — обновление индекса документа по URL:
- если документ новый — добавляет в индекс;
- если источник отвечает `404` — удаляет из индекса;
- если источник возвращает редирект — удаляет старый URL и индексирует новый.
- Доступ без авторизации; безопасность обеспечивается белым списком доменов (Source).

Также задокументирован способ встраивания виджета на сайт через единый JavaScript-сниппет (`https://chat.vbudushee.ru/widget`) с монтированием в контейнер `div#vchat-chat`.

### 3. Выбор и обоснование векторной базы данных

Проведён сравнительный анализ трёх архитектурных подходов. По итогам анализа выбрано расширение **PGVector для PostgreSQL**.

| Критерий | PostgreSQL + PGVector | Milvus / Weaviate | Chroma / LanceDB |
|:---|:---|:---|:---|
| On-premise размещение | ✅ Полное | ⚠️ Отдельный кластер | ✅ Встраиваемые |
| ТСО (оценка) | ✅ Минимальная | ❌ В ~5–7 раз выше | ⚠️ В ~2 раза выше |
| ACID и транзакционность | ✅ Полная | ❌ Нет | ❌ Нет |
| Гибридная фильтрация (SQL) | ✅ Максимальная | ⚠️ Собственный API | ⚠️ Средняя |
| Поддержка рос. провайдеров | ✅ Широкая | ⚠️ Ограниченная | ❌ Нет официальной |
| Документация на русском | ✅ Есть | ❌ Нет | ❌ Нет |
| HNSW-индекс | ✅ Встроен (v0.5+) | ✅ Встроен | ⚠️ Частично |
| Зрелость / Prod-ready | ✅ Высокая (25+ лет) | ⚠️ Средняя | ❌ Низкая |

**Ключевые аргументы в пользу PGVector:**

- **Единый контур безопасности:** бизнес-данные и векторы хранятся в одной БД; единый механизм аудита, RBAC и row-level security PostgreSQL.
- **Производительность:** HNSW-индекс обеспечивает субмиллисекундный поиск по миллионам векторов; покрывает целевую нагрузку 1000+ сессий в сочетании с масштабированием контейнеров.
- **Гибридная фильтрация:** семантический поиск объединяется с SQL-фильтрацией по метаданным («Паспорта материалов», категория, раздел) в едином запросе.
- **Технологический суверенитет:** PostgreSQL License (Open Source, без санкционных рисков); коммерческий дистрибутив **Postgres Pro** включён в Единый реестр российского ПО Минцифры.
- **Минимальный ТСО:** нет лицензионных затрат, не требуется отдельный сервер, используется стандартный SQL-стек без найма узкоспециализированных инженеров.

### 4. Правила индексации и цитирования источников

Разработан регламент индексации материалов Заказчика и стандарт формирования ссылок в интерфейсе чат-бота.

**Конвейер индексации (5 этапов):**
1. **Извлечение (Extract):** автоматический сбор файлов (Word, Excel, PDF, PPTX) из хранилища Заказчика; извлечение текстового слоя и метаданных (категория, дата, автор).
2. **Очистка и нормализация:** удаление непечатных символов, разметки, нормализация структуры текста.
3. **Разбиение на чанки (Chunking):** смысловое разбиение с перекрытием (overlap) для сохранения связности между фрагментами.
4. **Векторизация (Embedding):** отправка каждого чанка в GigaChat API для получения векторного представления.
5. **Сохранение:** запись векторов и метаданных в PGVector.

**Режимы переиндексации:**

| Режим | Описание | Применение |
|:---|:---|:---|
| Инкрементальный | Только новые или изменённые документы | Ежедневное обновление |
| Полный (Full Reindex) | Полная очистка БД и пересборка индексов | При смене модели GigaChat или изменении логики разбиения |

**Цитирование источников:** под каждым ответом выводится блок «Источники» с названием файла и прямой ссылкой на документ в АС «ВБУДУЩЕЕ». При наличии метаданных указывается конкретный раздел или страница (для PDF). Документы ранжируются по Similarity Score.

**Защита от галлюцинаций (Self-Consistency Check):** реализован механизм проверки того, что ответ модели не противоречит извлечённым документам. Если информация отсутствует в базе знаний, бот явно сообщает об этом, не формируя вымышленный ответ.

### 5. Политики кибербезопасности

Разработан полный комплекс политик безопасности на основе принципа эшелонированной защиты (Defense in Depth) и методологии SSDLC.

**Безопасность виджета (Client-Side):**
- санитизация всех ответов ИИ перед отображением в браузере (защита от XSS);
- Content Security Policy (CSP): скрипты и WSS/HTTPS-соединения разрешены только с доверенными эндпоинтами контура Фонда;
- изоляция сессий с ограниченным временем жизни; защита от перебора с блокировкой и записью в журнал аудита.

**Безопасность сервиса (Server-Side):**
- ORM-параметризация запросов (исключение SQL-инъекций в PostgreSQL);
- минимальные привилегии учётной записи БД (ограничены конкретными таблицами);
- TLS версии не ниже 1.2 для всех каналов связи, включая GigaChat API;
- соответствие 152-ФЗ при обработке персональных данных в форме обратной связи;
- хранение ключей API и паролей в системе управления секретами (Vault); хранение в исходном коде запрещено.

**Защита ИИ-слоя (LLM Guardrails):**
- защита системного промпта от просмотра и редактирования пользователем;
- валидация и блокировка prompt injection (команды «игнорируй предыдущие инструкции» и аналогичные);
- классификатор релевантности и фильтры безопасности для отклонения токсичного и нецелевого контента;
- Self-Consistency Check: ответ GigaChat не должен противоречить RAG-источникам;
- агенту запрещено исполнение кода, сгенерированного моделью; разрешён только текстовый вывод.

**Аудит и реагирование:**
- неизменяемый журнал всех событий: входы/выходы, попытки НСД, изменения прав доступа и системных настроек, все обращения к LLM (с маскированием ПДн);
- критические уязвимости (CVSS 7.5–10.0) устраняются в течение 5 часов с момента подтверждения;
- алерты и дашборды по ключевым метрикам безопасности (частота ошибок, попытки инъекций).

### 6. План наблюдаемости (Monitoring & Observability)

Разработан план мониторинга, охватывающий все ключевые аспекты работы системы. Общее число метрик на контейнер не превышает 1000 единиц (согласно ТЗ).

**Метрики Prometheus (Golden Signals):**
- **Latency:** общее время ответа чат-бота; цель — P90 < 20 секунд.
- **Traffic:** количество одновременных пользовательских сессий; цель — 1000+.
- **Errors:** частота HTTP 5xx и таймаутов API.
- **Availability:** статус доступности сервиса и AI-агента.

**Метрики RAG и GigaChat:** расход токенов и лимиты сессий, размер контекста (количество чанков), задержка векторного поиска, время до первого токена (TTFT) в потоковом режиме.

**Метрики индексации:** скорость индексации файлов, количество успешно обработанных документов, ошибки парсинга, объём данных и остаток дискового пространства.

**Алерты (Prometheus Alertmanager → почта Фонда):**

| Уровень | Событие | Условие |
|:---|:---|:---|
| 🔴 Красный | Service Down | Контейнер недоступен |
| 🔴 Красный | API Error Spike | Доля ошибок > 5% за 2 минуты |
| 🔴 Красный | SLO Violation | P90 ответа > 20 сек |
| 🟡 Жёлтый | Token Exhaustion | Прогноз исчерпания токенов < 24ч |
| 🟡 Жёлтый | Sync Stalled | Отсутствие обновлений в индексе > 12ч |

**Инструментарий:** Prometheus (эндпоинт `/metrics`), Grafana (дашборды SLO, GigaChat, индексация), GitLab (мониторинг конвейеров CI/CD). Логирование — в формате JSON с обязательными полями: `personalID`, `sessionID`, `Trace ID`, результат ответа.
