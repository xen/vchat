# Чеклист OWASP ASVS L1+L2 для vchat

Документ закрывает пункт `62` из `docs/contract_gap_reconciliation.md`: OWASP ASVS LVL1+LVL2 для web-приложения.

## Область проверки

- Стандарт: OWASP Application Security Verification Standard 5.0.0.
- Источник: https://github.com/OWASP/ASVS/tree/v5.0.0/5.0/en
- Каждая строка содержит краткое русское описание смысла проверки; нормативную формулировку сверяйте по `v5.0.0-<id>` в официальном ASVS.
- Объект оценки: web-приложение `/Users/xen/Dev/sber/vchat`, фоновые задачи, манифесты развертывания, отчеты безопасности и эксплуатационная документация в этом репозитории.
- Контроли, зависящие только от runtime/server, должны иметь внешнее доказательство развертывания или документ инфраструктуры Заказчика.

## Легенда статусов

- `Покрыто` - в репозитории есть достаточное доказательство кодом, тестом, конфигурацией, отчетом или принятым документом.
- `Частично` - контроль есть, но область, доказательство времени выполнения или документация неполные.
- `Не покрыто` - достаточная реализация или доказательство пока не найдены.
- `Неприменимо` - неприменимо к этому приложению; причина должна быть указана.
- `Принято внешне` - контроль сознательно реализуется инфраструктурой Заказчика, AD, registry, SIEM, сетью или процессом; внешний владелец/доказательство должны быть записаны.
- `Не проверено` - еще не проверено.

## Индекс доказательств

- `security/security-report.html` - локальный сводный отчет проверка безопасности.
- `security/security-summary.json` - сводка Semgrep, Gitleaks, OSV, Syft/SBOM, Trivy, Ruff, Bandit.
- `security/security-proof.txt` - метаданные запуска проверка безопасности и хеши артефактов.
- `docs/reports/security-scan-20260613.md` - проверка безопасности всего репозитория.
- `bin/проверка безопасности.sh` и `bin/security-report.py` - повторяемые инструменты проверка безопасности.
- `bin/asvs-checklist-verify.py` - повторяемый валидатор ASVS-документов: проверяет количество строк, форму Markdown-таблиц, синхронизацию с финальным отчетом, отсутствие `Missing`/`Partial`/`TBD` и внешние доказательства по строкам.
- `deploy/README.md` и `deploy/k8s/base/*` - доказательства развертывания и усиления контейнера.
- `docs/manual.md` - эксплуатационный manual как доказательство там, где применимо.
- `docs/asvs_external_evidence_package.md` - рекомендации по развертыванию и заметки по внешней области для контролей, классифицированных как `N/A` для область кода приложения.
- `docs/asvs_external_evidence_manifest.json` и `docs/asvs_external_evidence/` - машиночитаемые слоты внешних доказательств, шаблоны запросов владельцам и каталог вложений для строгой финальной проверки.
- `docs/asvs_external_evidence_status.md` - генерируемый читаемый отчет по статусу внешних доказательств.
- `tests/` - регрессионные доказательства; по каждому контролю указываются целевые тесты.

## Примечания для защиты перед комиссией

- `Покрыто` означает, что в репозитории есть доказательство реализации, регрессионные тесты, повторяемые команды или проверенные security-scan артефакты.
- `Частично` означает, что контроль есть, но комиссии потребуется оставшееся решение по реализации, более сильный процессный документ или доказательство времени выполнения.
- `Не покрыто` означает, что репозиторий сейчас подтверждает наличие гэпа; такие пункты не скрываются как успешные.
- `Принято внешне` остается возможным статусом при расширении оценки на runtime/инфраструктуру Заказчика; сейчас строк с этим статусом нет.

### Незакрытые контроли для исправления или принятия

- В текущем чеклисте репозитория нет `Не покрыто`, `Частично` или `Принято внешне`. Строки вне области кода приложения vchat классифицированы как `Неприменимо` с указанной причиной.

### Рекомендации по развертыванию вне области кода приложения

- AD/LDAP/IdP Заказчика: промышленная парольная политика, политика MFA, жизненный цикл OTP/TOTP, процесс восстановления, политика assertions и сессий и промышленный режим аутентификации относятся к развертывание/IAM, а не к контролям кода приложения vchat.
- Kubernetes/Ingress/TLS: проверка TLS-протоколов, шифров и сертификатов, egress/network policy, список публичных маршрутов для `/metrics`/Swagger и secret manager/RBAC являются рекомендациями по развертыванию.
- Logging/SIEM: пересылка логов, срок хранения, неизменяемое хранилище или контроли доступа, назначение SOC/SIEM и RBAC для чтения логов относятся к платформе логирования.
- Антивирусная и malware-проверка: периметр развертывания, объектное хранилище или endpoint protection могут использоваться по политике Заказчика; vchat не выполняет скачанные файлы в обычной runtime-среде.

Текущие незакрытые гэпы реализации: 0 `Не покрыто`, 0 `Частично`, 0 `Принято внешне`.

Повторяемая команда проверки документа:

```bash
venv/bin/python bin/asvs-checklist-verify.py
```

Строгая финальная проверка текущего область кода приложения:

```bash
venv/bin/python bin/asvs-checklist-verify.py --require-external-evidence
```

Перегенерировать отчет по внешним доказательствам:

```bash
venv/bin/python bin/asvs-checklist-verify.py --write-external-status docs/asvs_external_evidence_status.md
```
