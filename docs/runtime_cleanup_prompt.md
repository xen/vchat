Цель: чистить runtime-код проекта до fail-fast состояния без legacy-слоёв и декоративных обёрток.

Правила:

1. Удаляй fallback-логику, если она скрывает проблему инфраструктуры, данных или кода.
2. Не оставляй backward-compatibility aliases, deprecated entrypoints и legacy parsing без прямой необходимости.
3. Не проглатывай исключения через `except Exception: pass`, `return None`, `return False` или warning-only поведение там, где система должна упасть.
4. Если ошибка означает сломанную БД, Redis, Celery, сеть, модель, конфиг или неконсистентное состояние данных, она должна подняться с полным traceback.
5. Удаляй helper-функции и константы, если они:
   - используются в одном месте,
   - только прячут одну строку,
   - ухудшают читаемость переходами по файлу,
   - не выражают самостоятельную доменную сущность.
6. Не добавляй новые compatibility-слои, tolerant signatures, graceful degradation и мягкие обходы.
7. Если old-format данные или old-format API всё ещё реально нужны, сначала задаётся прямой вопрос владельцу проекта, а не добавляется совместимость “на всякий случай”.
8. Исторические миграции и архивные документы не переписываются в рамках обычной cleanup-задачи; чистится только актуальный runtime-код.
9. Если сигнатура функции получает параметры которые не используются, то вычищай их. Старайся уменьшать количество входных параметров в функции там где их больше 4.

Чеклист для каждого файла:

- Есть ли silent `except`?
- Есть ли логирование вместо падения?
- Есть ли legacy alias или legacy parser?
- Есть ли single-use helper или single-use constant?
- Есть ли `include_*`, `fallback_*`, `compat_*` параметры, которые больше не влияют на логику?
- Есть ли ветка “не получилось — просто пропустим”, хотя это реальная ошибка состояния?
- Есть ли возможность упростить сигнатуры функций?
- Есть ли места формирующие каскады запросов к базе данных в цикле которые можно уменьшить?

Результат cleanup:

- меньше кода;
- меньше скрытых режимов поведения;
- меньше неявной совместимости;
- больше прямых исключений и понятных tracebacks;
- меньше бессмысленных helper-функций и констант.
