# План индексации и правила цитирования источников

**Проект:** Сервис «ИИ-агент-чат-бот» для АС «ВБУДУЩЕЕ»
**Статус:** Отчетная документация (Этап 1)

### 1. Введение
Качество ответов ИИ-агента напрямую зависит от корректности подготовки данных. Данный документ определяет регламент первичной индексации материалов Заказчика, правила их обновления и стандарты формирования ссылок на источники в интерфейсе портала АС «ВБУДУЩЕЕ».

### 2. Процесс индексации данных (Pipeline)
Процесс автоматизирован и выполняется в контуре серверов Фонда.

#### 2.1. Этапы конвейера индексации
1. **Извлечение (Extract):**
   - Автоматический сбор файлов (Word, Excel, PDF, Power Point) из хранилища Заказчика.
   - Извлечение текстового слоя и связанных паспортных метаданных (категория, дата, автор).
2. **Очистка и нормализация:**
   - Удаление непечатных символов, разметки и нормализация структуры текста.
3. **Разбиение на фрагменты (Chunking):**
   - Текст разбивается на смысловые чанки с учётом ограничений контекстного окна GigaChat.
   - Максимальный размер контекстного окна GigaChat MAX — 32 768 токенов. Размер одного чанка фиксируется на уровне 512 токенов с перекрытием (overlap) 64 токена — это обеспечивает сохранность смысловой связности между фрагментами и оставляет достаточный резерв контекста для системного промпта и истории диалога.
4. **Векторизация (Embedding):**
   - Отправка каждого чанка в GigaChat API для получения векторного представления.
5. **Сохранение:**
   - Запись векторов и метаданных в векторную базу данных (на базе PostgreSQL).
   - Весь конвейер индексации выполняется единым сервисом-воркером на базе Celery. Celery обеспечивает распределение задач по воркерам, приоритизацию очередей и автоматический retry при ошибках (до 3 попыток с экспоненциальной задержкой). Более тяжёлые оркестраторы (Airflow, Prefect) не применяются как избыточные для данного объёма задач.
### 3. План переиндексации (Обновление данных)
Для поддержания актуальности базы знаний настроена регулярная синхронизация по расписанию.

#### 3.1. Стратегии обновления
* **Автоматическая синхронизация:** Сервис-коннектор проверяет хранилище на наличие новых или измененных файлов по расписанию.
* **Контроль версий:** Для каждого файла отслеживается статус (изменен/удален).
* **Дедупликация:** Перед векторизацией выполняется проверка на дубликаты для оптимизации расхода токенов и места в БД.

#### 3.2. Режимы обработки
| Режим                     | Описание                                                | Применение                                                |
| :------------------------ | :------------------------------------------------------ | :-------------------------------------------------------- |
| **Инкрементальный**       | Индексируются только новые или измененные документы.    | Ежедневное обновление.                                    |
| **Полный (Full Reindex)** | Полная очистка векторной БД и пересборка всех индексов. | При смене модели GigaChat или изменении логики разбиения. |

### 4. Правила цитирования источников
Согласно ТЗ, ответы чат-бота должны содержать обязательное указание источников.

#### 4.1. Формат отображения ссылок
Под каждым ответом ИИ-агента выводится блок «Источники» со следующими правилами:
* **Для документов:** `[Название файла] (Ссылка на файл в АС «ВБУДУЩЕЕ»)`.
  * *Пример:* Источник: [Положение о грантах.pdf](https://vbudushee.ru/storage/docs/grant.pdf).
* **Детализация:** Если метаданные позволяют, указывается конкретный раздел или страница (для PDF).
* **Группировка:** Если ответ сформирован на основе нескольких документов, они перечисляются списком в порядке значимости (по Similarity Score).

#### 4.2. Механизм верификации (Self-Consistency)
* **Проверка самосогласованности:** Реализован механизм проверки того, что ответ Модели не противоречит информации, извлеченной из документов.
* **Защита от галлюцинаций:** Если информация отсутствует в базе знаний, бот сообщает об этом, не выдумывая ответ.

### 5. Техническое обеспечение и мониторинг
Процесс индексации логируется и отображается в дашбордах мониторинга.
* **Метрики:** Отслеживается скорость индексации, количество успешно обработанных документов и ошибки парсинга.
* **Логирование:** Все операции по добавлению/удалению файлов фиксируются в журнале аудита для администраторов.
* **Инструменты мониторинга индексации:** метрики процесса индексации экспортируются в Prometheus через эндпоинт `/metrics` и визуализируются в Grafana. Отдельный дашборд отображает: скорость индексации (документов/мин), количество успешно обработанных документов, количество ошибок парсинга по типу файла, статус очереди Celery (ожидающие / активные / упавшие задачи). Подробная спецификация дашбордов — в документе `06_monitoring_and_observability.md`.
