# План индексации и правила цитирования (Core #4) 

## 1. Введение
Эффективная работа RAG-системы (Retrieval-Augmented Generation) напрямую зависит от качества подготовки данных. Данный документ описывает процессы первичной индексации, обновления данных (переиндексации) и механизмы цитирования источников в ответах ИИ чат-бота.

---

## 2. Процесс индексации данных

Процесс разделен на три основных этапа: **Сбор (Crawling)**, **Обработка (Processing)** и **Векторизация (Embedding)**.

### 2.1. Этапы конвейера
1.  **Извлечение (Extract)**: 
    - Для файлов (PDF, Docx): извлечение текстового слоя и метаданных.
    - Для сайтов: рекурсивный обход страниц (Crawler) и парсинг HTML-контента.
2.  **Очистка и нормализация**: Удаление лишних пробелов, HTML-тегов, приведение текста к единому формату.
3.  **Разбиение на чанки (Chunking)**: 
    - Метод: `chunk_text_word_window`.
    - Параметры: ~1000 токенов на чанк с перекрытием (overlap) в 150 токенов.
    - Цель: Сохранение контекста между соседними фрагментами.
4.  **Генерация эмбеддингов**: Отправка чанков в модель SentenceTransformer или внешнее API (OpenAI/Anthropic) для получения векторного представления.
5.  **Сохранение**: Запись текста и векторов в PostgreSQL с расширением PGVector.

---

## 3. План переиндексации (Обновление данных)

Система поддерживает несколько стратегий обновления данных для обеспечения актуальности базы знаний.

### 3.1. Триггеры обновления
| Тип триггера | Описание | Метод в коде |
| :--- | :--- | :--- |
| **Ручной (Источник)** | Переиндексация конкретного файла или сайта пользователем. | `refresh_source_index` |
| **Ручной (Проект)** | Полное обновление всех данных проекта. | `refresh_project_index` |
| **Полная пересборка** | Удаление всех чанков проекта и создание их заново. | `index_project` |
| **Автоматический** | Запуск по расписанию через Celery Beat (для веб-источников). | `crawl_all_sources_task` |

### 3.2. Механизм отслеживания изменений (Delta Updates)
Для предотвращения избыточных затрат на генерацию эмбеддингов используется хеширование:
- Для каждого документа (`Document`) вычисляется SHA-256 хеш контента.
- При переиндексации система сравнивает новый хеш с сохраненным в БД.
- Если хеш совпадает, этап генерации эмбеддингов для этого документа пропускается.

## 4. Правила цитирования источников

Цитирование необходимо для повышения доверия пользователя и возможности верификации ответа ИИ.

### 4.1. Формат ссылок
В интерфейсе чата ссылки на источники отображаются в формате Markdown или специальных UI-компонентов:

1.  **Для веб-страниц**: `[Заголовок страницы](URL)`
    - Пример: `[Инструкция по оплате](https://vbudushee.ru/docs/pay)`
2.  **Для локальных документов**: `[Название файла](file_id)`
    - Пример: `[Устав фонда](doc_82731)`

### 4.2. Механизм связки (Traceability)
Каждый ответ ИИ сопровождается списком ID чанков, которые были использованы для генерации. 
- **Модель `Chunk`**: Хранит `document_id` и `start_offset/end_offset`.
- **Поиск**: При получении ответа от LLM, система сопоставляет использованные контексты с исходными документами.
- **Отображение**: В конце сообщения или в виде сносок выводятся источники. Если чанк взят из PDF, может быть указана страница (если извлечена в метаданные).

### 4.3. Ограничения цитирования
- Если степень сходства (Similarity Score) чанка ниже установленного порога (например, 0.7), он не включается в цитирование, даже если попал в контекст.
- Если в проекте включен режим «Private», прямые ссылки на внешние ресурсы могут быть скрыты.

---

## 5. Техническое обеспечение (Celery Queues)

Для стабильности системы задачи разделены по очередям:
- `crawling`: Задачи по скачиванию сайтов и парсингу файлов.
- `embeddings`: Задачи по генерации векторов (требуют GPU или внешних API).
- `default`: Легкие задачи по управлению статусами.

---

## 6. Резюме
Текущий план индексации обеспечивает баланс между скоростью обновления (через хеширование) и качеством ответов (через глубокое разбиение на чанки с перекрытием). Правила цитирования гарантируют прозрачность работы алгоритмов RAG для конечного пользователя.
