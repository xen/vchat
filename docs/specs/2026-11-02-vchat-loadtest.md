# Task: Нагрузочные испытания VChat с эмулятором GigaChat

## Goal
Воспроизводимый отдельный инструмент, три измеренных сценария и опубликованный
отчёт с исходными данными: 1000 подключений, 100 конкурентных сообщений,
100 сообщений среди 1000 подключений.

## Context
- `vchat/views/chat/views.py`: WebSocket, защиты, поток, сохранение.
- `vchat/views/chat/ctx.py`: embedding, hybrid retrieval, cross-reranking.
- `jobs/embedder/client.py`: HTTP embedding; `vchat/db.py`: pool 5+10.
- `vchat/views/chat/guardrails.py`: текущий протокол GuardrailsAsyncOpenAI.

## Iterations
1. Изолированный локальный PostgreSQL со схемой VChat, синтетический корпус,
   отдельный Redis и реальные модели. Проверка: исходная БД не изменена.
2. Явный loopback HTTP-эмулятор OAuth/GigaChat SSE, запрет внешних соединений.
   Проверка: контракт SSE и неизвестный протокол возвращает явную ошибку.
3. Реальный WebSocket приложения, измерение входов/выходов обработчика,
   компонентов и ресурсов. Сценарии фиксированы до запуска: удержание 30 с,
   100 сообщений одной волной; таймаут 120 с; p90 полного ответа <20 с.
4. Отчёт, review, атомарная блокировка релиза, интеграция master и публикация.

## Verification
Проверяющий — текущий агент: контрактные тесты инструмента, реальные прогоны,
сверка клиентских ответов и записей БД, интервалов активности сервера, ошибок,
p50/p90/p95 первого содержимого и полного ответа. Число задач генератора само
по себе не доказывает 100 конкурентных обработчиков. Отсутствующий успешный
ответ не получает нулевую задержку. Несовместимость защит — открытый блокер,
а не основание отключить защиту. Одной волны недостаточно для длительного SLA.

## Guard Rails
Production не нагружается. Внешний GigaChat и реальные токены запрещены.
Защиты и runtime самостоятельно не переделываются. Чужие изменения и docs/psi
не трогаются. Иная эмуляция допускается только с явным описанием границы.
Публикация инструментов и документов не требует рестарта приложения.
