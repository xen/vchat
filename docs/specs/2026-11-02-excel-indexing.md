# Task: Индексация текста Excel

## Goal
Текст ячеек Excel доступен существующим индексированию и поиску. Тикет: https://github.com/xen/vchat/issues/2.

## Context
- `jobs/crawler/document_pipeline.py`: определение формата и extraction.
- `jobs/crawler/pipelines.py`: сохранение Page, ошибки и переиндексация.
- `jobs/crawler/spiders/general.py`: обнаружение и скачивание ссылок.
- `jobs/embedder/chunking.py`: разбиение текста с контекстом раздела.

## Target Shape
XLSX и XLSM читаются openpyxl как текст: название/состояние листа, номер строки, адрес ячейки, значение. Первая непустая строка служит только подписью столбцов следующих строк; это эвристика для читаемости, не распознавание произвольных таблиц. Контекст листа сохраняется в структуре и чанках. Повторная индексация Excel использует точное сравнение текста, включая числа.

## Guard Rails
- Макросы, формулы и внешние связи не исполняются и не обновляются. Формулы индексируются как выражения с пометкой `Formula (not evaluated)`; сохраненный вычисленный результат не используется.
- XLS и зашифрованные книги не поддержаны: явная ошибка. XLSM поддержан только в части обычных ячеек.
- Скрытые/veryHidden листы, строки и столбцы включены; видимость не является границей доступа. Состояние листа записывается в метаданные.
- Объединенные ячейки: текст только в исходной верхней левой ячейке, без размножения значений. Защита листа/структуры от редактирования не мешает чтению; парольное шифрование не снимается.
- Форматирование, диаграммы, изображения, комментарии, текст фигур и формат отображения чисел не извлекаются. Даты — ISO, числа — исходные значения. Пустая/поврежденная книга не становится пустым успехом. Формулы таблиц подстановки (data-table formulas) отклоняются явно; массивные формулы сохраняются как выражения. Превышение `embedding_document_max_chars` — явная ошибка, без подмены текстового индекса метаданными.
- Работа через существующие URL источников и скачивание crawler; отдельного интерфейса загрузки файлов проект не имеет. Новый upload API не создается.
- `docs/psi/`, чужие изменения и другие задачи не изменять.

## Iterations
1. Определение Excel по MIME, OOXML и расширению для общего бинарного MIME; ссылки разрешены crawler.
2. Извлечение, метаданные, точная переиндексация.
3. Unit/integration проверки, реальные образцы, сериализованное слияние и публикация.

## Verification
- XLSX/XLSM, общий MIME, пустые, поврежденные и XLS; формулы, hidden/merged/protected, даты/числа.
- Реальное извлечение внутри crawler pipeline и постановка индексации; неизмененная книга не ставится повторно, изменение числа ставится.
- Чанки содержат текст ячеек и контекст листа; существующий индекс/поиск использует эти Chunk.text.
- Две книги Phase 1 читаются без изменения исходников.
- Результаты проверок и публикации фиксируются после выполнения.

## Результат локальной проверки
- 22 теста Excel: извлечение, форматы/MIME, формулы, hidden/merged/protected, нули/False, ошибки, ограничения, обнаружение ссылок, чанки и повторная индексация — пройдены.
- Отдельный тест с настоящей PostgreSQL/pg_search: сохранение `Chunk`, поиск `fulltext_supply` в границах источника и замена значения при повторной материализации — пройден. Тест очищает собственные записи и сверяет количество Page/Chunk.
- Образцы Phase 1: «Вопросы, итерация 1 14.04.xlsx» — 152 ячейки, 17757 символов, 4 чанка; «Ресурсы фонда.xlsx» — 148 ячеек, 6455 символов, 3 чанка. Чанки проверены настоящим токенизатором; исходники не менялись.
- `ruff`, файловые pre-commit проверки и проверка типов extractor — пройдены. В общей проверке типов `pipelines.py` есть прежняя ошибка `build_source_id_by_host` (Sequence[Row] вместо list[tuple]), эта задача ее не меняет.
- Общий набор запускается через `DATABASE_URI=postgresql+asyncpg://xen@localhost:5432/vchat_excel_verify_20261102 make test`, после `make frontend` и создания отдельной БД со схемой ветки и заполненным тестовым виджетом. Общая локальная БД имеет другую схему и не мигрировалась.
- Итог общего прогона, commit и результат публикации фиксируются в тикете #2 после релиза.
- Финальный общий прогон с включенным `VCHAT_EXCEL_DB_URI` на отдельной БД: **808 passed, 2 skipped** (68.14 s); пропуски относятся к прежним опциональным проверкам. Smoke-тесты прошли с заполненным `welcome_messages` тестового виджета.
