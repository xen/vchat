# Инструкция по установке виджета на сайт партнера

Этот документ описывает, как партнеру разместить чат-виджет на своем сайте и
какие сетевые ограничения нужно проверить, если на сайте включены политики
безопасности браузера.

## Минимальный код установки

Разместите код на каждой странице, где должен быть доступен чат. Рекомендуемое
место вставки - перед закрывающим тегом `</body>`:

```html
<div id="vchat-chat"></div>
<script src="https://<домен-виджета>/widget/<код-виджета>" defer></script>
```

Где:

- `https://<домен-виджета>` - домен виджета, который передала команда vchat.
- `<код-виджета>` - уникальный код виджета из админки vchat.
- `div#vchat-chat` - обязательный контейнер для виджета.

Не меняйте `id="vchat-chat"`: скрипт ищет контейнер именно по этому
идентификатору.

## Опционально: передача данных пользователя

Этот раздел нужен только если сайт партнера хочет передавать в чат
идентификатор, имя или email текущего пользователя. Если такая передача не
нужна, весь раздел можно удалить: минимальный код установки выше продолжит
работать, а чат будет создавать гостевого пользователя.

Данные пользователя передаются одним атрибутом `data-user-info`. Внутри
атрибута должен быть JSON с timestamp и HMAC-SHA256 подписью:

```html
<div
  id="vchat-chat"
  data-user-info='{"timestamp":1710000000,"user_email":"ivan@example.com","user_name":"Иван Иванов","user_uid":"12345","signature":"<подпись>"}'
></div>
<script src="https://<домен-виджета>/widget/<код-виджета>" defer></script>
```

Поля JSON:

- `user_uid` - обязательный стабильный идентификатор пользователя на стороне
  сайта.
- `user_name` - опциональное имя пользователя.
- `user_email` - опциональный email пользователя.
- `timestamp` - обязательное Unix-время в секундах на момент формирования JSON.
- `signature` - обязательная HMAC-SHA256 подпись.

Подпись считается на секрете конкретного виджета. Секрет передает команда
vchat. Его нельзя отдавать в браузер отдельной переменной, публиковать в HTML
или хранить в открытых клиентских файлах. Формировать `data-user-info` нужно на
серверной стороне сайта партнера при генерации страницы.

Алгоритм подписи:

1. Соберите JSON-объект с полями `timestamp`, `user_uid` и, если нужно,
   `user_name`, `user_email`.
2. Не добавляйте поле `signature` на этом шаге.
3. Сериализуйте объект в JSON с сортировкой ключей и без лишних пробелов.
4. Посчитайте HMAC-SHA256 от этой строки, используя секрет виджета.
5. Добавьте hex-подпись в поле `signature`.
6. Передайте итоговый JSON в `data-user-info`.

Пример на Python:

```python
import hashlib
import hmac
import json
import time

widget_secret = "<секрет-виджета>"

user_info = {
    "timestamp": int(time.time()),
    "user_uid": "12345",
    "user_name": "Иван Иванов",
    "user_email": "ivan@example.com",
}
payload = json.dumps(
    user_info,
    ensure_ascii=False,
    sort_keys=True,
    separators=(",", ":"),
)
user_info["signature"] = hmac.new(
    widget_secret.encode("utf-8"),
    payload.encode("utf-8"),
    hashlib.sha256,
).hexdigest()

data_user_info = json.dumps(user_info, ensure_ascii=False, separators=(",", ":"))
```

При вставке значения в HTML-атрибут используйте штатное HTML-экранирование
вашего шаблонизатора.

Сервер vchat принимает только подписанный `data-user-info`. Если JSON изменили в
браузере, timestamp устарел или подпись не совпадает, чат не откроется для этих
данных и вернет ошибку `403`.

Срок действия подписи - 1 час. Если страница кэшируется целиком, не включайте в
кэш персональный `data-user-info` или формируйте его после кэша на серверной
стороне.

Поля пользователя не поддерживают HTML-разметку. Не передавайте в них HTML,
JavaScript, SVG или другие фрагменты кода.

## Опционально: явная передача URL страницы

Если URL страницы нужно передать явно, добавьте `data-source-page-url`:

```html
<div
  id="vchat-chat"
  data-source-page-url="https://example.com/page"
></div>
<script src="https://<домен-виджета>/widget/<код-виджета>" defer></script>
```

Если `data-source-page-url` не передан, виджет сам использует текущий
`window.location.href`.

## CORS и Access-Control-Allow-Origin

Партнерскому сайту не нужно настраивать CORS-заголовки для работы виджета.

В частности, партнеру не нужно добавлять `Access-Control-Allow-Origin` на своем
сайте ради подключения виджета. Виджет загружается как обычный `script`, а
интерфейс чата открывается в `iframe` с домена vchat.

CORS для запросов виджета настраивается на стороне домена vchat. Если браузер
показывает CORS-ошибки для адресов вида `https://<домен-виджета>/...`, их нужно
передать команде vchat вместе с текстом ошибки из DevTools.

## Content-Security-Policy

`Content-Security-Policy` или CSP - это HTTP-заголовок или meta-тег, которым
сайт ограничивает, откуда браузеру разрешено загружать скрипты, iframe,
шрифты, стили и сетевые соединения.

CSP не является CORS. CORS отвечает на вопрос: "разрешает ли удаленный сервер
читать ответ из браузера?". CSP отвечает на другой вопрос: "разрешает ли
текущий сайт вообще загружать ресурс с этого домена?".

Если на сайте партнера включена строгая CSP, она может заблокировать виджет
даже при корректной установке кода. В этом случае нужно разрешить домен vchat в
соответствующих директивах.

Пример фрагмента CSP:

```http
Content-Security-Policy:
  script-src 'self' https://<домен-виджета>;
  frame-src 'self' https://<домен-виджета>;
  child-src 'self' https://<домен-виджета>;
  connect-src 'self' https://<домен-виджета> wss://<домен-виджета>;
  font-src 'self' https://<домен-виджета>;
  style-src 'self' 'unsafe-inline';
```

Если CSP уже настроена, не заменяйте ее целиком этим примером. Добавьте
`https://<домен-виджета>` и `wss://<домен-виджета>` к существующим значениям.

Зачем нужны директивы:

- `script-src` - разрешает загрузить скрипт виджета.
- `frame-src` - разрешает открыть интерфейс чата в iframe.
- `child-src` - устаревшая, но иногда используемая директива для iframe в
  старых политиках.
- `connect-src` - разрешает запросы и WebSocket-соединение с доменом vchat.
- `font-src` - разрешает загрузку шрифтов виджета.
- `style-src 'unsafe-inline'` - нужен, потому что скрипт виджета добавляет
  стили на страницу через встроенный `<style>`.

### Где обычно меняют CSP

CSP обычно настраивается в одном из этих мест:

- в конфигурации веб-сервера: Nginx, Apache, Caddy;
- в CDN или WAF: Cloudflare, Fastly, Akamai и аналогичные сервисы;
- в настройках платформы сайта: CMS, конструктор сайта, корпоративный портал;
- в backend-приложении, которое отдает HTML-страницы;
- в HTML через тег `<meta http-equiv="Content-Security-Policy" ...>`.

Если сайт работает за CDN, проверьте и приложение, и CDN: CDN может добавлять
или переопределять CSP-заголовок поверх ответа приложения.

### Как посмотреть текущее значение CSP

В браузере:

1. Откройте страницу, где установлен виджет.
2. Откройте DevTools.
3. Перейдите на вкладку `Network`.
4. Обновите страницу.
5. Выберите основной HTML-документ страницы.
6. Откройте раздел `Response Headers`.
7. Найдите заголовок `Content-Security-Policy`.

Через командную строку:

```bash
curl -I https://example.com/page
```

В выводе нужно найти строку `Content-Security-Policy`. Если сайт делает
редиректы, используйте:

```bash
curl -IL https://example.com/page
```

Также проверьте вкладку `Console` в DevTools. При блокировке CSP браузер обычно
показывает ошибку вида `Refused to load script`, `Refused to frame`,
`Refused to connect` или `Refused to load the font`.

## Чего не делать

- Не подключайте виджет как `type="module"`.
- Не добавляйте атрибут `crossorigin`, если команда vchat отдельно этого не
  попросила.
- Не переименовывайте `id="vchat-chat"`.
- Не размещайте несколько контейнеров `#vchat-chat` на одной странице.
- Не блокируйте домен vchat в CSP, firewall, tag manager policy или настройках
  CDN.

## Проверка установки

После установки:

1. Обновите страницу.
2. В правом нижнем углу должна появиться кнопка чата.
3. При клике должен открыться iframe с чатом.
4. В DevTools не должно быть ошибок `404`, `403`, CORS или CSP для домена
   виджета.
5. Если кнопка не появилась, проверьте, что `div#vchat-chat` есть в DOM, а URL
   `https://<домен-виджета>/widget/<код-виджета>` открывается без ошибки.
