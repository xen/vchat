# Стратегия индексации сайтов проекта для АС «ВБУДУЩЕЕ»

Для организации индексации обширного списка сайтов в рамках АС «ВБУДУЩЕЕ», необходимо применить системный подход, разделяющий ресурсы по технологическому стеку и типу контента. Это позволит выполнить требования ТЗ по производительности и точности ответов ИИ-агента.

## 1. Категоризация ресурсов по технологическому стеку

Поскольку сайты проекта используют разные платформы (Bitrix, Laravel, WordPress, статический HTML), стратегия сбора данных должна адаптироваться под каждый тип.

### Группа А: CMS (Bitrix, WordPress, Laravel)

Это основные контентные ресурсы (напр., `vbudushee.ru`, `parents.vbudushee.ru`).

* **Метод:** Использование XML-карт сайта (`sitemap.xml`) для приоритизации индексации наиболее важных страниц.
* **Подготовка:** Исключение технических разделов (личные кабинеты, формы регистрации) через `robots.txt` или настройки правил краулера с помощью правил исключения по маске, чтобы ИИ не индексировал пустые или защищенные страницы.

### Группа Б: Интерактивные и JS-приложения (Javascript, Golang)

Сайты-тренажеры и игры (напр., `fg2024.vbudushee.ru`, `datalesson.ru`).

* **Метод:** Для индексации таких ресурсов краулер должен поддерживать рендеринг JavaScript (Headless browser), иначе текстовое содержимое не будет извлечено.
* **Анализ:** Необходимо определить, содержат ли эти ресурсы полезную базу знаний для ответов или они являются чисто функциональными инструментами.

Комментарий: возможность обхода сайта в формате SPA может быть существенно ограничен из-за особенностей работы краулеров.

### Группа В: Статические сайты (HTML)

Простые лендинги и витрины (напр., `eigame.vbudushee.ru`).

* **Метод:** Прямой рекурсивный обход страниц по расписанию.

## 2. Анализ структуры данных (Паспортизация)

Согласно ТЗ, каждый материал должен иметь «паспорт» (метаданные). Для сайтов это означает:

*   **Привязка к источнику:** Четкая маркировка каждого чанка текста URL-адресом конкретного поддомена.
*   **Тегирование:** Разделение контента по направлениям (напр., «Для родителей», «Финансовая грамотность», «Цифровые навыки») для повышения точности поиска.
*   **Формат ссылок:** Настройка правил цитирования так, чтобы бот выдавал прямую ссылку на соответствующий поддомен (напр., `catalog.vbudushee.ru`), а не на главную страницу.

## 3. Технический план подготовки (Pre-indexing)

### Шаг 1: Очистка контента (Normalization)

Перед отправкой в GigaChat необходимо очистить контент от «шума»:
*   Удаление навигационных меню, футеров и рекламных баннеров, которые дублируются на всех 30+ сайтах.
*   Извлечение только основного текста (Main Content Extraction), чтобы избежать замусоривания векторной базы данных.

### Шаг 2: Настройка частоты обновлений (Delta Updates)

Сайты имеют разную динамику обновлений:

* **Новостные и программные сайты** (напр., Грантовая платформа): Ежедневная проверка обновлений или по запросу через соответствующий метод API.
* **Архивные и методические материалы** (напр., Хрестоматия): Индексация раз в месяц или по ручному триггеру.

### Шаг 3: Безопасность и доступ

Поскольку многие сайты (напр., Грантовая платформа `grant.vbudushee.ru`) могут содержать закрытые данные, необходимо убедиться, что краулер имеет доступ только к публичным разделам. Все обращения краулера должны логироваться в системе мониторинга АС «ВБУДУЩЕЕ».

## 4. Сводная таблица приоритетов индексации

| Приоритет     | Ресурсы                                                                           | Цель индексации                                     |
| :------------ | :-------------------------------------------------------------------------------- | :-------------------------------------------------- |
| **Высокий**   | Главный сайт, Родители, Учителя, Каталог материалов                               | Ответы на вопросы по программам и методикам Фонда.  |
| **Средний**   | Грантовая платформа, Конкурсы, Проекты                                            | Информирование о текущих акциях и правилах участия. |

| **Через API** | В случае активного изменения контента через автоматизированный вызов API методолв | Определяется внутренними проектами фонда            |

**Рекомендация по организации:**

В проекте будет единый реестр источников в административном интерфейсе, где будет возможность мониторить какой контент был проиндексирован, как сформировалось его внутреннее представление для индексатора. Рекомендуется регулярно проверять состояние индекса и анализировать доступность документов для доступа пользователей.
